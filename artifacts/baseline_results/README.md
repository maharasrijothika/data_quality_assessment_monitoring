This directory is a **results-only audit baseline**. It does NOT modify code, models, KB, configuration, database, or existing production artifacts.

## Scope

- Databases inspected: `data/dq_assessment.db` (the live, writable DB; `backend/data/dq_assessment.db` is a 0-byte stale placeholder).
- Source tables: `datasets`, `dataset_versions`, `stored_profiles`, `semantic_runs`, `semantic_predictions`, `semantic_candidate_records`, `relationship_candidates`, `stage_states`.
- Artifacts scanned: `artifacts/profiling/<id>/<version>/profile.json`, `artifacts/semantic/<id>/<v>/{semantic_input.json,predictions.json}`, `artifacts/relationships/<id>/<v>/relationships.json`.

## Files produced
- `dataset_inventory.json` — every registered dataset + version.
- `profiling_results.json` — rows from `stored_profiles` (full `profile_json` preserved, plus `profile_id`, `row_count`, `created_at`).
- `semantic_results.json` — per version/run: run metadata, all `semantic_predictions`, alternative proposals, evidence JSON, and `semantic_candidate_records`.
- `relationship_results.json` — every `relationship_candidates` row: parent/child, role, score, evidence/stats JSON, status, `candidate_kind`, timestamps.
- `stage_execution_matrix.json` — one record per dataset/version: PRESENT/ABSENT/NOT_APPLICABLE/FAILED + run ids + artifact paths.
- `README.md` — this file.

## Status semantics
- PRESENT = the stage output artifact exists on disk (not merely a DB row).
- ABSENT = no artifact and no stored result for that dataset/version.
- FAILED = reported anywhere in DB/artifacts; see `warnings` section.
- NOT_APPLICABLE = dataset/version excluded from that stage (e.g., placeholder/duplicate registration).
